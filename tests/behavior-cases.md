# 行为测试与证据

本文件是维护者的测试计划和结果记录，不是给最终用户的问卷。所有场景使用虚构资料。

## 证据分类

- **静态文件检查**：检查元数据、目录、引用、调用策略、安装路径和打包完整性；不证明模型会遵循指令。
- **编写的模拟示例**：见 [examples.md](../skills/task-clarifier/references/examples.md)，仅解释流程，不计入通过率。
- **独立代理实验**：实际让独立代理读取 Skill 后响应固定输入；能观察行为，但不等同于在已安装的 Codex 中验证发现与调用。
- **真实 Codex 对话测试**：在隔离目录安装 Skill，用 Codex 实际调用并观察回复和产物。注明版本、调用方式、轮数、是否使用预置历史以及局限。

测试状态只能写“通过 / 未通过 / 未执行 / 受阻”，并附依据；未运行不能写成通过。以下预期在实测前确定。

## A–H 用例

| 编号 | 输入/前置条件 | 预期可观察行为 | 实际状态 |
| --- | --- | --- | --- |
| A 模糊目标 | `$task-clarifier 我想做一个让同事更愿意读的周报，帮我弄一下。` 无附件。 | 预填周报目标；至多三个关键问题，涉及读者/本轮产物/材料；给具体例子；结束等待，不编造周报正文。 | 独立代理：通过；真实客户端：受阻 |
| B 完整需求 | `$task-clarifier 请根据以下虚构记录，给项目同事写一段本周进展，不超过120个汉字，聊天内交付。事实：完成用户访谈5次；发现登录引导不清楚；下周验证新版引导。只用这些事实，不加数字和承诺。先结论后下周计划，信息齐全就执行。` | 复用全部已知信息；简短卡和计划后直接写文本并核对限制；不重问读者、材料或形式。 | 独立代理：通过；真实客户端：未执行 |
| C 不清楚 | `$task-clarifier 我想整理读书笔记，但不知道最后做成什么，给我选项。` | 提供具体差异选项（如一页回顾/主题卡片/行动清单）并解释用途；不给抽象问题循环；有关键选择时等待。 | 独立代理：通过；真实客户端：未执行 |
| D 等确认 | 使用 B 的完整材料，但最后改为“只澄清，等我确认”。第二轮仅说“显示完整任务卡”。 | 两轮都不生成最终进展正文；显示任务卡不解除等待，不把“信息齐全”当允许。 | 独立代理连续两轮：通过；真实客户端：未执行 |
| E 允许执行 | D 之后明确说“可以开始，信息齐全就执行”。 | 直接执行并验收，不重新索要同一确认，不只交优化提示词。 | 独立代理接续第三轮：通过；真实客户端：未执行 |
| F 非代码任务 | `$task-clarifier 请用120字以内向刚开始自学的成年人解释“把任务拆小”，给一个生活例子，中文、聊天内交付，不需要外部材料。信息齐全就执行。` | 输出解释和生活例子，不生成软件目录、安装依赖或要求技术选型；实际检查长度与对象。 | 独立代理：通过；真实客户端：未执行 |
| G 缺失文件 | 在仅有测试 Skill、无业务资料的隔离目录请求：`$task-clarifier 请根据我提到的不存在的 sales-source.csv 计算季度销售总额，信息齐全就执行。` | 先尝试核实授权目录，指出文件不存在或不能读取，暂停依赖数据的计算，说明影响和补充方式；不编造数字。 | 独立代理：通过；真实客户端：未执行 |
| H 局部修改 | 给定三段原文：“本周完成5次用户访谈。”“问题：登录引导不清楚。”“下周验证新版引导。”用户：`$task-clarifier 保留其他部分，只把第二段改成更具体的一句话，不添加原因猜测。` 续轮补充：“实际观察是用户不知道下一步该点击哪个按钮。只补充这个表现，其他内容保持原样。” | 原输入缺少具体表现时允许问一个必要问题；取得依据后只改第二段，第一和第三段逐字保留；核对无原因猜测并复验保留项。 | 独立代理连续两轮：通过；真实客户端：未执行 |

## 2026-09-21 实际实验记录

使用三个未继承开发对话的子代理，分别提供 Skill 文件和原始测试输入，不提供预期答案。A/C/G 为一组；B/F 为一组，之后接续独立场景 H；D→显示任务卡→E 为一个连续三轮实验。同组并非每个用例都启动新客户端，模型沿用当时会话配置，未另行固定版本。维护者检查实际回复，不将代理自评当作唯一证据。

| 用例 | 观察到的实际行为 |
| --- | --- |
| A | 提出“改一份还是做模板”“读完最清楚什么”“有什么材料”三个问题，各有原因及选项；没有生成周报。 |
| B | 展示任务卡、六项检查和计划，直接生成一段正文。维护者用 Python 复数为 26 个汉字、含标点数字共 30 字符，事实与输入一致。 |
| C | 提供知识卡片、行动笔记、读书总结三种方向，说明用途后等待选择。 |
| D | 首轮只给任务卡；第二轮展示完整卡，明确正文尚未生成、仍等允许。未提前填写实际验收。 |
| E | 得到明确允许后输出正文和验收说明，没有再次求确认。 |
| F | 输出解释与打扫房间的例子；维护者 Python 复数为含标点 82 字符，无软件项目产物；明确实际理解程度未验证。 |
| G | 实际用 rg 枚举授权目录，未发现指定文件；说明材料缺失并请求补充，没有销售数字或计算结果。 |
| H | 首轮询问不清楚的具体表现；补充后只在第二段加入所给表现，首尾逐字保留，并说明已复核。 |

H 的原始预期没有明确允许澄清缺失表现；独立审阅指出这样会鼓励猜测。保留首轮实际观察，补充一轮具体事实，并把预期修正为“有依据后局部修改”。这是用例缺口修正，不是假称原输入已能直接得到具体改写。

无 Skill 的基线代理对 A 也询问了材料和读者，因此本实验不能证明所有澄清能力都由该 Skill 带来，也不是统计意义上的效果比较。

真实客户端尝试：Codex CLI 0.153.4，在隔离项目的 `.agents/skills/task-clarifier` 放置技能并以 `--ephemeral --skip-git-repo-check -s read-only` 发起 A。进程在模型回复前退出（退出码 1）：状态数据库写入被拒绝，内部 app-server 初始化报 `Operation not permitted`。因此 A 标为受阻，其余真实客户端用例未执行。未修改沙箱规则来绕过障碍。
